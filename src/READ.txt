YepFootball - Latest Scores persistence update

FILES
-----
1. index.js
2. app.js

IMPORTANT CLOUDFLARE SETUP
---------------------------
The Worker code requires this KV binding:

Binding name: LATEST_SCORES
KV namespace: the KV namespace you use for YepFootball daily scores

The Worker also requires these secrets:

API_FOOTBALL_KEY
FOOTBALL_DATA_TOKEN

LATEST SCORES BEHAVIOUR
-----------------------
- Before 23:50 Europe/Paris: the last successful daily snapshot remains visible.
- At/after 23:50: today's completed results are published when API-Football succeeds.
- If API-Football fails at 23:50: the previous snapshot is retained.
- A later request after the API recovers will publish the new snapshot.
- app.js also stores the last successful snapshot in the browser localStorage.
- A temporary API failure therefore does not blank the Latest Scores section.

CRON
----
The Worker scheduled handler checks Paris local time and publishes at 23:50.
Make sure your Cloudflare Worker has a Cron Trigger that runs at least hourly,
and preferably at 23:50 Europe/Paris converted to the appropriate UTC time.

If you already have a Cron Trigger running regularly, no change is required
in the code.

MATCH CENTRE
------------
/match-centre continues to use API-Football live data and app.js refreshes it
every 30 seconds.

DEPLOY
------
Upload/replace index.js in the Worker project and app.js in the website assets.
Then deploy the Worker and the website.

TEST
----
1. Open /api/health
2. Open /api/scores
3. Confirm /api/scores returns source: API-Football
4. Refresh the website.
5. Temporarily make the scores API unavailable and confirm the previous scores
   remain visible in the browser.
